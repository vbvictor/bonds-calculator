# CLAUDE.md

Инструкции для агента по проекту **bond-rate-calculator**.

Читать целиком перед первой строкой кода. Полное ТЗ — в отдельном документе (`SPEC.md`, если приложен); этот файл самодостаточен по части математики и приёмочных критериев.

---

## Что строим

Статическое SPA: пользователь задаёт свой прогноз траектории ключевой ставки ЦБ РФ и сравнивает несколько облигаций (флоатеры и фиксы) по фактической доходности к погашению с учётом реинвестирования купонов.

Главный выходной артефакт для пользователя — **точка безразличия**: насколько должна измениться траектория, чтобы победитель поменялся.

## Стек

Vite + React 18 + TypeScript (strict) + Recharts 2.x + Vitest. Деплой — GitHub Pages через Actions.

## Модель. Реализовать ровно так

### Соглашения

- `FACE = 1000` всегда.
- Шаг времени — **один месяц**. Месяц 0 — дата старта расчёта.
- Ставки на входе в процентах (14.0), внутри модели в долях (0.14).
- `H` — срок до погашения в месяцах, общий для всех бумаг.
- Удержание до погашения. Дефолта нет. Продажи раньше нет.

### Траектория ставки

Ключевая ставка меняется **скачками**, только в даты заседаний, и между ними постоянна. Линейная интерполяция физически неверна — она есть, но как опция.

```ts
type RateAnchor =
  | { kind: 'date';   value: string }    // ISO
  | { kind: 'offset'; months: number }

type RatePoint = {
  id: string
  anchor: RateAnchor
  rate: number                            // проценты
  confidence: 'confirmed' | 'estimated'
}
```

Перевод даты в индекс месяца:

```
m = (year(date) - year(start)) * 12 + (month(date) - month(start))
```

Дробная часть отбрасывается: 1 и 23 октября дают один индекс. Это сознательное упрощение, вытекающее из помесячного шага.

```
ksAt(m, shift, mode = "step"):
  если m <= path[0].m     → path[0].r + shift
  если m >= path[last].m  → path[last].r + shift

  mode "step" (умолчание):
    найти последнюю точку i, у которой path[i].m <= m
    → path[i].r + shift

  mode "linear" (опция):
    найти i: path[i].m <= m <= path[i+1].m
    w = (m - path[i].m) / (path[i+1].m - path[i].m)
    → path[i].r + (path[i+1].r - path[i].r) * w + shift
```

Кусочно-постоянна, непрерывна справа. `shift` — параллельный сдвиг в п.п. для сценарного анализа, по умолчанию 0.

### Купоны

`step = round(12 / freq)`. Выплаты в месяцы `step, 2*step, ...` включительно до `H`.

Фикс и дисконтная:
```
coupon = FACE * couponRate / freq
```

Флоатер — ставка устанавливается на начало купонного периода со сдвигом на лаг:
```
setMonth = max(0, m - step - lag)
rate     = ksAt(setMonth, shift) / 100 + spread
coupon   = FACE * rate / freq
```

### Реинвестирование

```
rMM(t) = ksAt(t, shift) / 100 + reinvSpread

grow(amount, from):
  v = amount
  для t от from до H-1 включительно:
    v = v * (1 + rMM(t) / 12)
  вернуть v
```

**Два места, где легко ошибиться:**
- Цикл до `H-1`, не до `H`. Купон, пришедший ровно в месяц `H`, не растёт вообще.
- Номинальная капитализация: делим годовую ставку на 12. **Не** извлекаем корень 12-й степени. Так работают фонды денежного рынка.

### Результат

```
pot    = Σ grow(coupon_k, m_k)
FV     = FACE + pot
price  = pricePct / 100 * FACE
return = (FV / price)^(12 / H) - 1
```

### Ряд для графика

Одним проходом, не повторными вызовами `grow`:

```
pot = 0
для t от 0 до H:
  если t > 0: pot = pot * (1 + rMM(t-1) / 12)
  прибавить купоны, выпадающие ровно на месяц t
  series[t] = (FACE + pot) / price
```

Последний элемент ряда **обязан** совпадать с `FV / price`. Вынести в тест.

### Сценарный анализ

`shift` от −6.0 до +2.0 п.п., 71 точка. Точка безразличия между парой бумаг — первая смена знака разности доходностей, уточнить линейной интерполяцией между соседними узлами.

### Средняя ставка

```
avgKS = Σ ksAt(t, shift) для t от 0 до H / (H + 1)
```

## Приёмочные тесты

Эталоны получены `reference/ref.py`. Допуск 1e−6 по доходности, 1e−3 по суммам. Расхождение — ошибка в реализации, не в эталоне.

### A. Плоская ставка

`path = [{0, 14.0}]`, `H = 36`, `reinvSpread = 1%`

| Бумага | FV | Доходность |
|---|---|---|
| Флоатер КС+1.5%, цена 100, freq 4, lag 0 | 1575.5180 | 16.3611% |
| Фикс 15.5%, цена 99, freq 2 | 1564.7952 | 16.4861% |

Первый купон флоатера ровно **38.75**.

### B. Снижение ставки, режим step

`path = [{0,14.0},{6,13.5},{12,12.5},{24,10.5}]`, `H = 36`, `reinvSpread = 1%`, lag 1

| Бумага | FV | Доходность |
|---|---|---|
| Флоатер КС+1.5%, цена 100.2, freq 4 | 1507.5118 | 14.5859% |
| Фикс 15.5%, цена 99, freq 2 | 1545.5842 | 16.0074% |

Разрыв −1.4216 п.п., `avgKS` = 12.2027%.

Те же данные в режиме `linear` дают −1.88 п.п. и 11.80%. Расхождение почти в полпункта — это проверка того, что режим действительно ступенчатый.

### C. Ступенчатость

На траектории B, режим `step`:

| Месяц | 0 | 5 | 6 | 11 | 12 | 23 | 24 | 36 |
|---|---|---|---|---|---|---|---|---|
| Ставка | 14.00 | 14.00 | 13.50 | 13.50 | 12.50 | 12.50 | 10.50 | 10.50 |

Месяц 5 даёт 14.00, месяц 6 уже 13.50.

Режим `linear` на той же траектории: 13.75 на месяце 3, 13.00 на месяце 9, 11.50 на месяце 18.

### D. Дисконтная бумага

Купон 0, цена 75, `H = 36`, ставка 0, реинвест 0 → `(1/0.75)^(1/3) − 1 = 10.0642%`.

### E. Инвариант ряда

Последний элемент помесячного ряда = `FV / price` с точностью 1e−9. Property-based, не менее 100 случайных входов.

### F. Границы

- `H` не кратен шагу купона (`H = 35`, freq 2): последний купон на месяце 30, номинал на 35.
- Одна точка в траектории — ставка постоянна везде.
- `lag` больше купонного периода — `setMonth` не уходит ниже нуля.
- Битый URL — поднимаемся на дефолтах, не падаем.
- Цена ≤ 0 — блокировать на вводе, в модель не пускать.

### G. Реальный календарь

`path = [{0,14.0},{1,13.5},{3,13.0},{5,12.5},{6,12.0},{7,11.5},{9,11.0},{10,10.5},{12,10.0}]`, параметры бумаг как в B, `H = 36`, режим `step`.

| Бумага | Доходность |
|---|---|
| Флоатер КС+1.5%, цена 100.2 | 12.9296% |
| Фикс 15.5%, цена 99 | 15.7705% |

Разрыв −2.8409 п.п. Неравномерные интервалы (1, 2, 2, 1, 1, 2, 1, 2 месяца) ловят ошибки поиска последней применимой точки.

### H. Эквивалентность режимов

При одной точке в траектории `step` и `linear` дают побитово одинаковый результат.

## Ключевые UX-требования

- **Сводка результатов идёт сразу под шапкой**, до всех форм. Пользователь должен видеть ответ, а не анкету.
- Пересчёт немедленный, без кнопки «Рассчитать».
- Даты заседаний вводятся **свободно**. Любая дата допустима, включая несовпадающую с реальным заседанием. Не исправлять, не подсвечивать как ошибку.
- Точку можно задать датой или сдвигом «через N месяцев». Переключается на каждой строке, позиция сохраняется.
- Генератор сетки: ритм (как у ЦБ 8 раз в год / каждые N месяцев), число точек, шаг ставки, пол или потолок. Генерирует обычные строки, которые можно править поштучно.
- Всё состояние в URL (версионировано, `v=1`), дубль в `localStorage` с try/catch. URL приоритетнее.

## Грабли Recharts

- Линия ключевой ставки — `type="stepAfter"`. Иначе график покажет плавные наклоны там, где ставка стоит на полке. Линии доходности — `type="monotone"`.
- Не передавать `var(--x)` в пропсы Recharts. Читать токены через `getComputedStyle(document.documentElement).getPropertyValue('--float')` в объект темы, перечитывать при смене темы. Хук `useThemeTokens()`, подписан на `matchMedia('(prefers-color-scheme: dark)')` и на `data-theme`.
- `ResponsiveContainer` внутри `overflow-x: auto` зацикливается на измерении ширины. Задавать контейнеру явные min-width и height в пикселях.
- Дефолтный `Tooltip` не умеет русскую локаль чисел. Писать свой.

## Деплой

`vite.config.ts`:
```js
base: '/bond-rate-calculator/',   // имя репозитория, слэши с обеих сторон
```

Без этого Pages отдаст белый экран с 404 по ассетам.

Workflow `.github/workflows/deploy.yml` с `permissions: {contents: read, pages: write, id-token: write}`, `actions/upload-pages-artifact@v3` + `actions/deploy-pages@v4`. Тесты запускать **перед** сборкой: разошлась модель с эталонами — деплоя быть не должно.

После первого пуша один раз выставить **Settings → Pages → Source → GitHub Actions**. Не ветка. Это самая частая причина «всё зелёное, а страницы нет».
